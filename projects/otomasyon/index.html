“Appium yalnızca işletim sisteminin çizdiğine dokunabilir. AltTester ise Unity'nin çizdiği her şeyi sürer ve doğrular.” “Appium only taps what the OS draws. AltTester drives and asserts everything Unity draws.” — projenin çıkış cümlesi— the project's thesis

Çözdüğü problemThe problem it solves

Bir Unity oyunu tüm arayüzünü işletim sistemi açısından tek bir opak yüzeyin içine çizer. Appium bu yüzeye koordinatla dokunabilir ama “bakiye tam olarak 4.000 oldu mu” sorusunu soramaz. AltTester ise Unity'nin nesne ağacının içine uzanır — ama izin diyalogları, satın alma onayları ve uygulama yaşam döngüsü gibi native katmana kördür. A Unity game draws its entire interface inside what the OS sees as one opaque surface. Appium can tap that surface by coordinate, but it cannot ask “did the balance become exactly 4,000?”. AltTester reaches into Unity's object tree — but it is blind to the native layer: permission dialogs, purchase confirmations, app lifecycle.

Yani “Satın Al'a bas → native onay diyaloğu çıksın → onayla → cüzdana tam 5.000 yazılsın” akışını tek başına hiçbir sürücü test edemez. Bu proje ikisini tek bir test oturumunda, tek bir case gövdesinde birleştiriyor. Which means neither driver alone can test a flow like “tap Buy → a native confirmation appears → accept → the wallet credits exactly 5,000”. This project unifies both into a single session and a single case body.

Dört tasarım kuralıFour design rules

1 · Tek locator kaynağı1 · One locator set

Erişilebilirlik id'leri bir kez NativeIds.cs içinde tanımlanır; Android'e contentDescription, iOS'a accessibilityIdentifier olarak yayılır. Python tarafı ile C# tarafı ayrışırsa PF-01 senaryosu yüksek sesle patlar.Accessibility ids are declared once in NativeIds.cs and published as contentDescription (Android) / accessibilityIdentifier (iOS). If the Python mirror drifts from the C# source, case PF-01 fails loudly.

2 · Case gövdesi platform bilmez2 · A case body names no platform

Platform farkları PlatformOps arayüzünün arkasında yaşar. Bir kanal o platformda uygulanamıyorsa PlatformUnsupported ile adıyla atlanır — sessizce geçilmez.Platform differences live behind the PlatformOps seam. A channel that cannot be implemented raises PlatformUnsupported by name — it is never silently skipped.

3 · Kesintiler araya serpiştirilir3 · Interruptions are interleaved

13 kesinti senaryosu kendi kategorisinde park etmez; kestikleri kategorinin id'sini taşır (C-08, LC-05 değil). Davranış ekseni etiketlerle taşınır.The 13 interruption cases are not parked in their own bucket; each carries the id of the category it interrupts (C-08, not LC-0x). The behavioural axis is carried by tags.

4 · Her senaryo ön koşulunu kendi kurar4 · Every case sets up its own state

Koşum sırası bir anlatıdır, bağımlılık zinciri değil. Herhangi bir senaryo tek başına, herhangi bir sırada çalışabilir. Oyunda kalıcılık bilerek kapalı — her açılış sıfırdan başlar.Run order is a narrative, not a dependency chain. Any case runs alone, in any order. Persistence in the game is deliberately off — every launch starts fresh.

Üç kırmızı bilerek duruyorThree reds are left standing on purpose

Tabloyu yeşile boyamak kolaydı. Boyamadım — çünkü hiç kırmızıya dönmemiş bir test paketi, kırmızıya dönebildiğini kanıtlamamıştır. Üçü de gerçek ve üçü de farklı bir şey öğretiyor: Painting the table green would have been easy. I didn't — because a suite that has never gone red has not been shown to be capable of going red. All three are real, and each one teaches something different:

J-02 Testin kendi zamanlama yarışıA timing race in the test itself iOS
Dünya durumu, bobbin yerleştirildikten 1,46 sn sonra okunuyordu — ama Level 01'de bobbin ömrü ~1,5 sn. Nesne meşru şekilde yok olmuştu; ürün değil test hatalıydı. Üç okuma tek bir yeniden deneme döngüsüne alındı, kozmetik bekleme kaldırıldı: okuma artık 301 ms'de yapılıyor ve Android'de geçiyor.World state was read 1.46 s after deploying a bobbin — but on Level 01 a bobbin lives ~1.5 s. The object was legitimately gone; the test was wrong, not the product. All three readings moved into one retry loop and a cosmetic settle was removed: the read now happens at 301 ms and passes on Android.
LC-05 --fast bayrağının açığa çıkardığı gerçek yarışA genuine race exposed by --fast Android
İki ölçüm beklemesi yanlışlıkla kozmetik hız düğmesine bağlanmıştı, dolayısıyla --fast onları sıfırladı. Bu, paketteki gerçek bir sınıflandırma hatasıydı: kozmetik bekleme sıfırlanabilir, ölçüm beklemesi asla. Yerine ön plana gerçekten geçilene kadar yoklayan _await_foreground() kondu (6 sn tavan).Two measurement waits had been wired through the cosmetic pace knob, so --fast zeroed them. That was a real classification bug in the suite: a cosmetic settle may be zeroed, a measurement wait never. They were replaced with _await_foreground(), which polls until the foreground genuinely moves (6 s ceiling).
PF-03 Ön kontrolün kendi hatasıA defect in the preflight itself Unity Editor
Editor modundaki backend kontrolü "Editor" / "Mock" için büyük-küçük harfe duyarlı bir alt dize testiydi; oysa NativeProbe.BackendName 'editor-mock' cevabını veriyor. Üçüncü senaryoda, 0,05 sn içinde patladı — tam da bir ön kontrolün yapması gereken şey.The Editor-mode backend check was a case-sensitive substring test for "Editor" / "Mock", but NativeProbe.BackendName answers 'editor-mock'. It blew up on the third case in 0.05 s — exactly what a preflight gate should do.

Otomasyonun bulduğu iki gerçek ürün hatasıTwo real product defects the automation found

ScreenWakeLock

15. kategori native senaryo içermeyen tek blok — dolayısıyla dokuz dakika boyunca yalnızca AltTester üzerinden koşuyor. AltTester dokunuşları Unity'nin içine enjekte edildiği için işletim sisteminin boşta kalma sayacını hiç sıfırlamıyor: telefon kendini kilitledi, iOS uygulamayı askıya aldı, soket koptu ve WDA oturumu öldü. Odaktayken Screen.sleepTimeout = NeverSleep ile çözüldü.Category 15 is the only block with no native case, so it runs for nine straight minutes purely through AltTester. Because AltTester taps are injected inside Unity, they never reset the OS idle timer: the phone auto-locked, iOS suspended the app, the socket closed and the WDA session died. Fixed with Screen.sleepTimeout = NeverSleep while focused.

AltTesterHostBuildStep

Yeni kurulan bir iOS derlemesi, AltTester bağlantı diyaloğunda sonsuza kadar bekliyordu. Sürücü host'u artık derleme zamanında build adımıyla gömülüyor; koşum insan müdahalesi olmadan başlıyor.A freshly installed iOS build used to stop at the AltTester connection dialog forever. The driver host is now baked in at build time by a build step, so a run starts with no human in the loop.

CI/CD — gerçek cihazlarda, ücretsizCI/CD — on real devices, for free

Cihaz bulutlarının kalıcı ücretsiz katmanı yok; Firebase Test Lab yalnızca Espresso/XCTest türü koşumları kabul ediyor ve host tarafında bir Python süreci çalıştıramıyor — üstelik AltTester bağlantıyı cihazdan host'a doğru kuruyor, yani bir veri merkezindeki telefonun benim makinemin :13000 portuna rotası yok. Bu yüzden kendi Mac'imi self-hosted runner yaptım. Device clouds have no permanent free tier; Firebase Test Lab only accepts Espresso/XCTest-shaped runs and cannot host a Python process — and AltTester dials out from device to host, so a handset in someone's datacentre has no route to my machine's :13000. So I turned my own Mac into a self-hosted runner.

Tek komut, beş fazOne command, five phases

lane.sh editor|android|ios
PREPARE → BUILD → SERVE → RUN → RESET. Faz sıralamasını script sahiplenir, workflow değil — böylece yerelde ve CI'da aynı şey çalışır. PREPARE → BUILD → SERVE → RUN → RESET. The script owns the phase order, not the workflow — so local and CI run the same thing.

İptal edilse bile temizlerResets even when cancelled

Reset bir EXIT trap'ine bağlı; SIGTERM/SIGINT sinyalleri exit'e çevriliyor. Doğrulandı: kill -TERM tam bir reset sonrası 143 döndürüyor. Yarıda kalan koşum çalışma ağacını kirli bırakmıyor. Reset hangs off an EXIT trap, and SIGTERM/SIGINT are converted into an exit. Verified: kill -TERM returns 143 after a full reset. A killed run never leaves the tree dirty.

Anlamlı çıkış kodlarıExit codes that mean something

75 = atla, kusur değil (telefon takılı değil).
4 = artefakt güvenilmez: APK 30 MB'ın altındaysa IL2CPP stripping enstrümantasyonu yemiştir. Yeşil bir koşum yalancı olmasın diye. 75 = skip, not a defect (handset unplugged).
4 = artefact not credible: an APK under 30 MB means IL2CPP stripping ate the instrumentation. So that a green run can't be a lie.

Ölçülmüş kurulum notu:A measured setup note: Runner, oturum açmış GUI kullanıcısı altında bir LaunchAgent olarak çalışmak zorunda — Unity lisansı kullanıcı başına, kod imzalama kilidi açık anahtarlığa muhtaç, Editor lane'i ise bir pencere sunucusu istiyor. iOS derlemesinin “15–30 dakika sürer” varsayımı da yanlış çıktı: ölçülen 112,4 sn (Unity→Xcode 40 sn, xcodebuild + imzalama 50 sn). The runner must run as a LaunchAgent under the logged-in GUI user — the Unity licence is per-user, codesigning needs the unlocked login keychain, and the Editor lane needs a window server. The assumption that an iOS build takes “15–30 minutes” also proved wrong: measured 112.4 s (Unity→Xcode 40 s, xcodebuild + signing 50 s).
